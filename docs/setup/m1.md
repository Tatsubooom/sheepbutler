# M1 メールの取り込み

大学メールが専用 Gmail に届くと、Gmail → Pub/Sub → Cloud Run の順に通知が届き、Firestore の `messages` に保存されます。
M0 が完了している（`go run ./cmd/m0check` がすべて ✓）ことが前提です。

```
専用 Gmail ──watch──▶ Pub/Sub(gmail-push) ──push──▶ Cloud Run /pubsub/gmail ──▶ Firestore messages
Cloud Scheduler（毎日 4:00）──▶ Cloud Run /jobs/renew-watch（7日で切れる watch を張り直す）
```

## 仕組み

- **差分の取得**：Firestore の `state/gmail` に「ここまで処理した」という履歴 ID を持ち、Gmail の履歴 API でそれ以降に受信トレイへ追加されたメールだけを取得する。
- **二重処理の防止**：保存先のドキュメント ID を Gmail のメール ID にし、既にあれば保存しない。Pub/Sub の再送や通知の重複があっても結果は同じになる。
- **失敗時**：途中で失敗したら履歴 ID を進めずに 500 を返す。Pub/Sub が 10 秒〜10 分の間隔で再送し、続きから処理する。
- **初回**：過去のメールは遡らず、watch を登録した時点から取り込む。
- **履歴の期限切れ**：長く止まっていて履歴 ID が古くなった場合は、直近 7 日の受信トレイを取り直す。
- **保存内容**：差出人、宛先、件名、冒頭の抜粋、受信日時のみ。本文は保存しない。`expiresAt`（受信日時＋90日）を過ぎると TTL で自動削除される。
- **アクセス制御**：Cloud Run は認証必須で、Pub/Sub と Scheduler が使う `sheepbutler-invoker` だけが呼べる。

## デプロイ

`gcp-setup.sh` を M0 の後に更新しているので（Firestore の TTL を追加）、もう一度実行してからデプロイする。

```bash
PROJECT_ID=<プロジェクトID> ./scripts/gcp-setup.sh
PROJECT_ID=<プロジェクトID> ./scripts/deploy.sh
```

## 動作確認

1. 大学アドレスにテストメールを送る。
2. 1 分ほど待ってログを見る。

   ```bash
   gcloud run services logs read sheepbutler --region asia-northeast1 --limit 20
   ```

3. 「同期しました」のログで `created` が 1 以上なら成功。Firestore コンソールの `messages` にも保存されている。

## ローカルで試す

Cloud Run にデプロイせずに、手元から1回だけ同期できる。Firestore への接続にはアプリケーションのデフォルト認証情報が必要。

```bash
gcloud auth application-default login
# .env に GOOGLE_CLOUD_PROJECT=<プロジェクトID> と GMAIL_PUBSUB_TOPIC=projects/<プロジェクトID>/topics/gmail-push を追加
go run ./cmd/server -once renew-watch   # 初回の起点を記録
go run ./cmd/server -once sync          # 起点以降のメールを取り込む
```

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| `deploy.sh` のビルドで権限エラー | Cloud Build が使うサービスアカウント（既定は Compute Engine のデフォルト）に `roles/run.builder` を付与する。エラーメッセージに対象のアカウントが表示される |
| ログに `watch の登録` のエラー（403） | `gcp-setup.sh` の Pub/Sub トピックへの権限付与（`gmail-api-push@system.gserviceaccount.com`）が済んでいるか確認 |
| 通知が来ない（ログに何も出ない） | `gcloud pubsub subscriptions describe gmail-push-sub` で push 先 URL を確認。Scheduler のジョブを手動実行して watch を張り直す: `gcloud scheduler jobs run renew-gmail-watch --location asia-northeast1` |
| ログに 401 / 403（Pub/Sub → Cloud Run） | 2021 年 4 月より前に作ったプロジェクトでは、Pub/Sub のサービスエージェントに `roles/iam.serviceAccountTokenCreator` が必要 |
| `invalid_grant` エラー | OAuth 同意画面が「テスト」のままでトークンが失効した可能性。本番に切り替え、`go run ./cmd/authorize` と `upload-secrets.sh` をやり直して再デプロイ |
