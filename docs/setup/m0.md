# 準備（外部サービスの用意）

外部サービスのアカウントと権限を用意し、`go run ./cmd/m0check` がすべて ✓ になれば M0 は完了です。
所要時間の目安は 1〜2 時間です。手順の多くはブラウザでの手作業です。

| # | やること | 確認方法 |
|---|---|---|
| 1 | 専用 Gmail を作る | 2段階認証が有効 |
| 2 | メールを専用 Gmail に転送する（複数アカウント可） | m0check「メールの転送」 |
| 3 | メインのカレンダーを専用 Gmail に共有する | m0check「Google カレンダー」 |
| 4 | Google Cloud プロジェクトを準備する | `scripts/gcp-setup.sh` が完了 |
| 5 | OAuth 同意画面とクライアントを作る | `go run ./cmd/authorize` が成功 |
| 6 | Discord Bot（または LINE）を用意する | m0check「通知のテスト送信」 |
| 7 | Claude API キーを用意する | m0check「Claude API」 |
| 8 | 接続を確認し、秘密情報をクラウドに登録する | m0check がすべて ✓ |

---

## 0. 必要なツール

- Go 1.26 以上
- Git Bash（スクリプトの実行に使う）
- Google Cloud CLI: `winget install Google.CloudSDK` でインストールし、新しいターミナルで `gcloud auth login`

## 1. 専用 Gmail を作る

1. 大学メール受信専用の Gmail アカウントを新しく作る。他の用途には使わない。
2. **2段階認証を必ず有効にする**（Google アカウント → セキュリティ）。
   大学のメールがすべて集まるアカウントなので、乗っ取られたときの被害が大きい。

## 2. メールを専用 Gmail に転送する

読ませたいアカウントはすべて専用 Gmail に転送して集約する。どのアカウント宛てだったかは SheepButler が判別して記録する。

**大学（Outlook）**

1. [Outlook on the web](https://outlook.office.com) に大学アカウントでログインする。
2. 設定（歯車）→ メール → 転送 を開く。
3. 「転送を有効にする」をオンにし、転送先に専用 Gmail のアドレスを入れる。
4. 「転送されたメッセージのコピーを保持する」をオンにする（大学側にも原本を残す）。

**Gmail（個人アカウントなど）**

1. 転送元の Gmail で 設定 → すべての設定を表示 → メール転送と POP/IMAP →「転送先アドレスを追加」に専用 Gmail を入れる。
2. 専用 Gmail に届く確認コードを入力して承認する。
3. 全件を転送するか、フィルタ（設定 → フィルタとブロック中のアドレス）で必要なメールだけを転送するかを選ぶ。メルマガなども転送すると、判定に使う LLM の費用が増える。

**共通**

- `.env` の `MAIL_SOURCES` に、転送元を「ラベル=アドレス」で `;` 区切りに並べる。
  例: `MAIL_SOURCES=大学=12abc345@ms.dendai.ac.jp;個人=someone@gmail.com`
- それぞれのアドレスにテストメールを送り、専用 Gmail に届くことを確かめる。

## 3. カレンダーを共有する

OAuth のトークンは専用 Gmail のものだけを使う。メインアカウントのカレンダーは、専用 Gmail に共有して読めるようにする。

1. メインアカウントで Google カレンダーを開き、自分のカレンダーの「設定と共有」を開く。
2. 「特定のユーザーまたはグループと共有する」に専用 Gmail を追加する。
3. 権限は **「予定の表示（すべての予定の詳細）」** にする（変更権限は与えない）。
4. `.env` の `GOOGLE_CALENDAR_ID` にはメインアカウントのアドレスを入れる。

## 4. Google Cloud プロジェクトを準備する

1. [Google Cloud コンソール](https://console.cloud.google.com) でプロジェクトを作る（メインアカウントで構わない）。
2. 請求先アカウントを紐付ける。Cloud Run などは無料枠内でも請求先の登録が必要。
3. Git Bash でセットアップスクリプトを実行する。

   ```bash
   PROJECT_ID=<プロジェクトID> ./scripts/gcp-setup.sh
   ```

   API の有効化、Firestore、Pub/Sub トピック、Cloud Run 用サービスアカウント、Secret Manager の箱を作る。
4. コンソールの「お支払い → 予算とアラート」で予算アラートを設定する（例：月 500 円）。

## 5. OAuth 同意画面とクライアントを作る

コンソールの「Google Auth Platform」で操作する。

1. **ブランディング**：アプリ名 `SheepButler`、サポートメールは自分のアドレス。
2. **対象**：ユーザーの種類は「外部」。
3. **データアクセス**：スコープに次の2つだけを追加する。
   - `https://www.googleapis.com/auth/gmail.readonly`
   - `https://www.googleapis.com/auth/calendar.readonly`
4. **対象 → 公開ステータス**：「アプリを公開」を押して **本番環境** にする。
   > 「テスト」のままだとリフレッシュトークンが 7 日で失効し、毎週再認可が必要になる。
   > 本番にしても審査は不要（個人利用）。認可時に「Google はこのアプリを確認していません」と出るので、「詳細 → SheepButler（安全ではないページ）に移動」で進む。
5. **クライアント**：「クライアントを作成」→ 種類は **デスクトップ アプリ**。JSON をダウンロードし、`.secrets/client_secret.json` として保存する。
6. `.env.example` を `.env` にコピーし、値を埋める（Discord・Claude の値は後の手順で入れる）。
7. 認可を実行する。ブラウザが開くので、**専用 Gmail** でログインして許可する。

   ```bash
   go run ./cmd/authorize
   ```

   `.secrets/token.json` が作られれば成功。

## 6. 通知先を用意する

### Discord（推奨）

1. 自分だけが入る Discord サーバーを作り、通知用のチャンネル（例：`#butler`）を作る。
2. [Discord Developer Portal](https://discord.com/developers/applications) で New Application → `SheepButler`。
3. Bot タブで「Reset Token」を押してトークンをコピーし、`.env` の `DISCORD_BOT_TOKEN` に入れる。
   特権インテント（Privileged Gateway Intents）はすべてオフのままでよい。
4. OAuth2 → URL Generator で、Scopes に `bot` と `applications.commands`、Bot Permissions に `View Channels` と `Send Messages` を選ぶ。生成された URL を開いて、手順 1 のサーバーに招待する。
5. Discord の設定 → 詳細設定 → 開発者モードをオンにし、通知用チャンネルを右クリック →「チャンネル ID をコピー」。`.env` の `DISCORD_CHANNEL_ID` に入れる。

### LINE（Discord の代わりに使う場合）

1. [LINE Developers](https://developers.line.biz) で Messaging API チャネルを作る（LINE 公式アカウントの作成を伴う）。
2. チャネルアクセストークン（長期）を発行し、`.env` の `LINE_CHANNEL_ACCESS_TOKEN` に入れる。
3. チャネル基本設定の「あなたのユーザー ID」を `.env` の `LINE_USER_ID` に入れる。
4. 自分の LINE でこの公式アカウントを友だち追加する。
5. `.env` の `NOTIFY_CHANNEL` を `line` にする。

## 7. Claude API キーを用意する

1. [Claude Console](https://console.anthropic.com) で API キーを作り、`.env` の `ANTHROPIC_API_KEY` に入れる。
2. Console の Limits で月の利用上限を低め（例：5 ドル）に設定しておく。

## 8. 接続を確認し、秘密情報を登録する

```bash
go run ./cmd/m0check
```

すべて ✓ になったら、秘密情報を Secret Manager に登録する（M1 以降、Cloud Run はここから読む）。

```bash
PROJECT_ID=<プロジェクトID> ./scripts/upload-secrets.sh
```

---

### うまくいかないとき

| 症状 | 対処 |
|---|---|
| `authorize` で「アクセスをブロック」と出る | 同意画面のスコープが2つとも登録されているか、公開ステータスを確認 |
| `authorize` でリフレッシュトークンが返らない | 専用 Gmail の「Google アカウント → セキュリティ → サードパーティ製アプリ」から SheepButler を削除して再実行 |
| 「メールの転送」が ✗ | 表示されたアドレスにテストメールを送ってから再実行。迷惑メールフォルダも確認 |
| 「Google カレンダー」が 404 | 手順 3 の共有と、`GOOGLE_CALENDAR_ID` のアドレスを確認 |
| Discord で 403 | Bot がサーバーに招待されているか、チャンネルの閲覧・送信権限を確認 |
